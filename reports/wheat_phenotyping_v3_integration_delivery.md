# 麦视通 V3.0「智能分析与生长趋势整合版」交付报告

## 1. 交付范围

本轮整合已有可靠能力，没有重新训练模型，也没有改变 V1.1 规则的权重和等级阈值。当前单张图片入口仍以真实上传图片为输入，按以下顺序执行：图片校验与 RGB 读取、选择的植被分割算法、覆盖率/绿色程度/空间均匀度计算、图像质量检查、V1.1 规则初评，以及可选的 CGIAR 七阶段生育期模型推理。

V1.1 评分继续使用：

`0.45 × 覆盖评分 + 0.35 × 绿色评分 + 0.20 × 均匀评分`

评分等级继续使用 80～100“长势较好”、60～79“长势一般”、0～59“长势较弱”。这些结果仍明确标为“图像表观规则初评”，不是经过农学专家校准的诊断模型。

## 4. 当前可以演示的功能

1. 打开长势分析页面，上传 JPG、JPEG 或 PNG 小麦图片。
2. 选择 ExG、HSV、Otsu-ExG 或 ExG-HSV Fusion 中的一个冻结方案。
3. 点击“开始分析”，查看真实原图、植被掩膜、叠加图、覆盖率、绿色程度、空间均匀度、图像质量、V1.1 综合分、等级、可靠性、优势和改善建议。
4. 页面会自动尝试 CGIAR 七阶段识别；模型可加载时显示七阶段概率和置信度，低置信度时提示人工复核。
5. 输入稳定的地块编号后重复上传同一地块图片，可在“我的报告”中查看同一地块的历史变化；不填写地块编号的记录不会被自动拼接成生长曲线。
6. 在“我的报告”中查看原图和叠加图、评价依据，并导出 JSON 分析记录。

后端和前端启动方式：

```powershell

.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000

# 前端（另一个 PowerShell）
cd D:\Desktop\wheat\source-code\wheat-phenotyping\frontend
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`。前端 API 地址由 `VITE_API_BASE_URL` 控制；未设置时使用当前同源配置。

## 5. 模型与科研边界

- V1.1 是可解释的图像表观规则初评，不是深度学习长势诊断。
- CGIAR 七阶段模型只表示生育期分类，不表示长势好坏；当前训练/验证范围来自 CGIAR 数据，不能直接外推到中国品种、地区或手机拍摄域。
- FoMo4Wheat 仍作为冻结视觉特征骨干使用，原始权重没有覆盖。
- EWS 只用于植被/背景分割验证，不是叶片、茎秆、麦穗器官真值。
- 没有经过验证的未来模型前，不提供 7/15/30 天数值、开花日期、产量、收益或市场价格预测。
- 记录中的 `plot_id` 必须由用户或实验流程提供；系统不会凭不同用户的图片、文件名或时间自动猜测同一地块。

## 6. 遗留问题

1. 需要在本机正常的 Uvicorn/浏览器运行环境中继续定位 Windows 内嵌 ASGI 测试客户端的阻塞，以补充真正的 HTTP 自动化测试。
2. 需要建立带地块、年份、环境和拍摄批次元数据的独立外部验证集，才能评价七阶段模型的地块独立泛化能力。
3. 需要专家人工长势标签和生育期条件下的校准数据，才能替换或校准 V1.1 规则。
4. GSP-AI 的模型输出语义和 FS 定义仍需官方证据确认；在此之前保持不可用状态。
